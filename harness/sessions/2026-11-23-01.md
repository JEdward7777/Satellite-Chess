## What was learned

- **The review rounds**, all on one symptom, *the game silently resumes on the old field*. Each round found the next hole beside the last fix.
  - **R1 (FIX).** The server side was verified sound. Two holes:
    - A lost `recalibrate` frame was never re-sent, so the player resumed on the old field with the saved field already new.
    - No field shape check: string coordinates went into the arithmetic and corrupted stored moves mid-game.
    - Fixed: re-send per socket; the shape check in the shared `gameFieldOf`.
    - The first attempt used all of `asFieldSpec`. That refused a same-field create with a malformed `origin` (`record.test.ts`), so the check covers only what a snapshot keeps.
  - **R2 (FIX).** The automatic `ready`, judged on the old snapshot, beat the re-send on reconnect. `net.ts` notifies open-listeners before sending `sync`, and the re-send waited a microtask. The game resumed on the old field.
    - Fixed: the gate (`pending()`; ready, button and relays held), and the re-send only after the socket's first snapshot.
    - Relays had to be held too: a relay raises the flag on the server as surely as `ready`.
  - **R3 (FIX).** The unconfirmed recalibration lived only in memory. A reload, a discarded tab, leaving and re-entering, or "Recalibrate" then "Not now" lost it (4/4).
    - R2 had ruled that case an observation. A second opinion sided with R3: players walking corners outdoors are exactly when mobile browsers discard tabs.
    - Fixed: stored per game, keyed by account `sub` (the server applies it to whatever seat the socket holds, so keying is the client's job), resumed on every board, button hidden, "Sending…" line.
  - **R4 (CLEAN).** Three small nits taken without another round, read by the coordinator: an older-over-newer guard (`superseded`), a null-record guard, and a corner-shape check on the stored record.
- **Driver lessons:**
  - Recalibrated fields sync to the account and came back down on the next run's phones. Use a fresh account per run.
  - A page-level `routeWebSocket` installed after load never fired. Install it on the context before the page opens.
  - A carry must be walked, not teleported, or the server refuses it as implausible.
