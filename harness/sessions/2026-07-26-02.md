## What was learned

**The relay ceiling is 599 messages per player per 30 minutes, and speed is
irrelevant.** Identical at 0.7, 1.4 and 3 m/s: the 2.5 s interval floor binds long
before the 2 m delta does, and a 1 Hz offer stream can only clear a 2,500 ms floor
every *third* tick — hence 599 rather than 720. That is above the 250–450 the
budget doc estimated, so worst case is ~1,290 requests per game and ~77 games a
day rather than 90–140. `harness/reference/budget.md` now carries both: the
estimate as typical, the measurement as the ceiling. A stationary player sends
exactly one relay message however long they stand there, so any real game lands
between 1 and 599.

**A working capture looked broken because of a test predicate.** `lastMove.to === 'd5'`
was already true from black's `d7-d5`, so white's `e4xd5` matched the opponent's
stale broadcast and returned the wrong move. That is the **second** instance of
this shape; logged as **O-07**, with the structural fix if it recurs — every
snapshot already carries a monotonic `rev`, so `next()` could ignore anything
older than the caller's last-seen revision.

**I wrote a vacuous test and the integration test caught it.** An `async` reader
handed to a synchronous polling helper returns a Promise, which is always truthy,
so the assertion passed against nothing. Worth remembering as a shape: any
`until(...)`-style helper needs an awaiting variant, or it silently accepts
anything asynchronous.

**The server's relay backstop fires against a legitimate client.** The `ready`
handshake records a position, so a relay sent immediately after falls inside
`POS_SERVER_MIN_INTERVAL_MS` and is discarded — and the client's limiter cannot
know, having sent nothing yet. Not a bug on either side; both are doing their job.
Both halves are now asserted.

**Assert material, not notation.** The capture tests count pawns (8 → 7) rather
than trusting the `x` in the SAN, because the SAN comes from the same library
under test.
