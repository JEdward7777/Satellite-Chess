## What was done

Cleared the browser-driver backlog, which had reached three sessions deep, and
found one real defect by doing it.

**Playwright, without root and without touching the system.** Three sessions had
recorded "playwright is not installed in the container" as a standing fact and
deferred the drivers each time. That was true of the containers and is not true
of the operator's own machine: `PLAYWRIGHT_BROWSERS_PATH` puts chromium in one
folder under `~/.cache`, `--with-deps` (the part that needs `apt-get`) turned out
to be unnecessary on WSL2, and the whole thing is removed with one `rm -rf`. The
recipe is in `reference/container.md` so nobody re-derives it. Deliberately not
under the repo: this tree lives inside `Sync/` and 658 MB of browser has no
business being synced.

**All eleven drivers now pass**, the first run of any of them since 2026-08-03.
Three had never been run at all. Four bugs, all in the drivers rather than the
product:

- `check-fields.mjs` nudged the *first* phone to sync the instant the *second*
  phone's rename was clicked — racing a push that is unawaited by design
  (decision 0013). It now waits on the account, which is the actual
  precondition. Same fix for the delete.
- It clicked delete once. The UI arms and re-labels on the first tap and deletes
  on the second, which is deliberate and which a driver that has never been run
  has no way of discovering.
- It waited for an empty `<ul>` to be *visible*. An empty list has no height, so
  it was waiting for the one outcome the step existed to rule out.
- Every driver counted the browser's `401` resource line as a console error. A
  signed-out phone asking the account for its fields and its games is told 401
  **by design**, and that is most runs until `2.5.1`. `scripts/driver-console.mjs`
  now holds that rule once, narrowed to those two endpoints at that one status,
  so a 500 — or a 401 from anywhere else — still fails.

**`scripts/check-games.mjs` is new** and closes O-14: the signed-out phone shows
no section rather than an empty heading, a game reaches another phone of the same
account, tapping a line takes the same seat, a stranger sees nothing, and the
tidy-up offer starts with nothing ticked.

**The home screen's game list is now capped** (`HOME_SHOWN = 5`), with the rest
one tap away, expanded in place rather than on a screen of its own.

## What was learned

**The first screenshot of the new list showed a defect no test could have
caught, which is exactly what this project keeps predicting.** Seven games
pushed the field list, Calibrate, New game and the join-code box off the bottom
of the page. I had even written a test asserting the cause — *"never hides a game
that is still going, however many there are"* — which is a fair description of a
list and a bad description of a home screen.

**Measuring beat redesigning.** The obvious next move was to reorder the screen.
Measured at 480x900 first: "New game" sits at y=542 with no games, y=709 with
one, and crosses the fold at **three**. So a cap could never deliver "above the
fold", and — the part that changed the decision — **the fields list above it has
the same shape, with a limit of two hundred**. The ordering problem is older and
bigger than this stage. The cap stays because it bounds the half this stage
introduced; the rest is O-16, for a session that means to do it.

**The driver assertion had to become a bound rather than a fold**, for the same
reason. `check-games.mjs` asserts that home fits in two screens with seven games,
which is true, stays true, and is what the cap is actually for. Asserting the
fold would have been asserting something the design does not provide.

**A stale "we can't do that here" is more expensive than a stale bug.** The
backlog existed because a constraint got written down once and then inherited
three times without being retested. Nothing had changed about the drivers; the
box had changed. Worth re-checking any sentence in the harness that begins "X is
not available".

**Verification.** 709 tests (was 706 — three more for the cap), typecheck and
`plan:check` green, and all eleven drivers run against a real `wrangler dev`
after the client change, not before it.
