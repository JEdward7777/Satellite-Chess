## What was done

Phase 10 of run 2 (`harness/pipeline/ratchet.md`), to the owner's 2026-10-04
design in O-37: family indoors watch the game being played outside, live,
with both players visible. Decision 0055 records it.

- **Consent.** One new inbound message, `watch` with `on` or `off`, one per
  tap. One player's `on` asks; the other's `on` agrees, and only then is there
  a link. `off` from either withdraws, declines or turns it off. Only while
  both seats are taken and the game is not over. An unanswered request lapses
  on a pause or a disconnect suspension; a link already agreed to stays on.
- **The link** is `/w/<object id>.<secret>`. The id is the game's Durable
  Object id, so the Worker reaches the game with `idFromString` and the link
  never holds the join code. The secret is 128 random bits in `meta`
  (`watch_token`), new each time watching is turned on, compared in constant
  time. No session is read on the watcher's socket.
- **The watcher's view** (`watch_state`, `watch_pos`) is built field by field
  on the server: squares from a1's centre to a hundredth, moves, clocks, both
  dots, last move, piece in hand, walked distances, board size (to a
  hundredth of a meter). No coordinate, field, name, bearing, accuracy,
  reach, join code or account. A dot more than 3 squares off the board is
  sent as no position. A player's message is never sent to a watcher.
- **Watchers are nobody to the game.** Tagged `watcher`, attachment
  `{ watcher: true }`; every `getWebSockets()` loop asks `isPlayer` or
  `isWatcher`. Arriving or leaving touches no presence row, timer or
  revision. Anything a watcher sends closes it (4004).
- **The link dies** when either player turns it off (4001) and when the game
  ends, finished or aborted (final view, then 4002), in the same synchronous
  step that deletes the secret.
- **Cap of six** (`WATCH_MAX_WATCHERS`); the seventh is accepted and closed
  with 4003, and its page does not retry. **No coaching delay.**
- **The watcher's page** (`client/views/watch.ts`, `watch-draw.ts`,
  `watch-net.ts`) is mounted before the simulator, the location provider
  and the sign-in gate. It draws the replay's unit board with zoom, both dots
  (white or black inside a red "person" ring, so a dot reads on its own
  side's pieces), the piece in hand beside the carrier, clocks, moves and
  distances in the device's units (the locale's when signed out), both
  looks, and a flip. It sends nothing but the free keepalive.
- **The players' control** (`client/watching.ts`, `views/game.ts`): "Let
  people watch" on the board opens a panel (ask, wait, agree or decline; once
  on, the link, a QR, Share, Copy, "Turn watching off"). The opponent's ask is
  a banner with Agree dead for a second. A line says when watching is on.
- The privacy statement has a paragraph on watching. `budget.md` and
  `gotchas.md` have sections.

## What was learned

- **Build a second audience's view apart, never by trimming.** A field added
  to the players' snapshot later would leak by default; built field by
  field, it is absent until someone adds it on purpose.
- **A Durable Object id is a lookup-free, code-free address.** `idFromString`
  reaches the same object as `getByName(code)`, and an id not from this
  namespace throws, so a link needs neither a table nor the code.
- **Accept-and-close is how a refusal reaches a browser.** A failed upgrade
  tells the page nothing; a socket accepted under its own tag and closed with
  a 4000-range code tells it why.
- **A dot on a piece of its own color disappears.** Players stand on the
  square they just placed on; the watcher's dots needed a ring.
