## What was learned

- **`wrangler secret put` on a Worker that does not exist yet offers to create
  it.** The operator ran the secret before the first `deploy`; wrangler created
  a bare code-less Worker named `satellite-chess` with just the secret, and the
  subsequent `deploy` uploaded the code onto it with the secret intact. Order
  did not matter. Creating it that way does skip the `workers.dev` subdomain
  prompt, but `deploy` handles that.
- **Setting `SURVEY_SECRET` takes effect on the live Worker immediately — no
  redeploy.** The `/api/survey/*` routes went 404 → live the moment the secret
  landed.
- **The container's 403 is real and this confirmed the workaround.** Everything
  that touches the Cloudflare API — `login`, `deploy`, `secret put` — has to be
  the operator's from a local clone. Nothing else does: all eight browser
  drivers and `wrangler dev --local` still work in the container.
- **The Claude Code auto-mode classifier blocks `wrangler deploy` / `secret
  put` even locally.** They surface as hard denials, not permission prompts, so
  the operator runs them via the `!` prefix and pastes the output back.
