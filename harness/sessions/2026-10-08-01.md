One new decision, **0054**: head-to-head is folded from each player's own
record rows, grouped by a **pair id**, and the opponent's name is the
reader's own. It amends 0040 rule 4 ("no opponent").

- **Who the opponent was.** The game hashes both players' `sub`s (sorted,
  SHA-256 under a label, 128 bits of hex: `pairIdFor` in
  `worker/user-record.ts`) once, keeps it in `meta.pair_id`, and puts it in
  both record lines, with the other player's distance. No row holds the
  other account's `sub`, email or name. Pairwise rather than per player, so
  two people comparing lists cannot discover a third person they both played.
- **Exactly once.** The two new fields are part of the line, so they ride
  the existing digest and upsert-by-join-code. No new write, no new timer.
  A finished game still on the server gets them when its line is next sent.
- **The same tally on both phones.** Each account folds its own rows
  (`summarizeHeadToHead`, `shared/head-to-head.ts`) oldest first, ties by
  code, so both agree to the bit once both lines for each game have landed.
  Only counted games enter the tally; a game is unmeasured if either
  distance is (`pairStandingOf`).
- **Meters first.** "154 m walked between you", then "You 56 m · They 98 m",
  then the results. `walkedPairWords` (`shared/units.ts`) makes the total
  the sum of the two figures shown while it is in the short unit.
- **Names.** No Google name or email. A nickname (40 characters, cleaned)
  lives in the reader's own `opponent_names` table and only for a pair id
  already in their record. Unnamed: "Unnamed opponent, first played Oct 8
  at Sim Field".
- **Routes.** The list rides on `GET /api/record` (still one call into the
  account). `GET /api/record/opponent?id=|?game=` and `POST
  /api/record/opponent/name` read and write the session's own account only;
  anything not in it is the same 404 as something that does not exist.
- **Older rows** have no pair id. They are left out and counted ("2 earlier
  games were recorded before…"). Aborted games write no row (0050).
- **Screens.** "Against each opponent" under the record on the account
  screen; the opponent screen (`client/views/opponent.ts`); "Your record
  against this player" on the review, for a seat in a game with a result.
- **Schema.** User schema 4: `record.pair_id`, `record.opponent_travel_m`
  (by `ALTER` on old accounts) and `opponent_names`.
- **Privacy statement.** A "Who you played" bullet.
- **`scripts/check-h2h.mjs`.** Three phones. A and B play four games
  (Fool's mate, a resignation, an agreed draw, an abort), every piece
  carried. Then: one opponent each, the same pair id, three games each and
  not the abort, the same meters to the bit, results mirrored, the same line
  on both account screens, A's nickname never on B's side, B reaching it
  from a review, US units in yards. A third account gets an empty list and
  the plain 404 for the pair id, both codes and naming, and nothing from
  guessed paths.
- **Tests: 1328 → 1359.** `test/head-to-head.test.ts` sweeps a thousand
  random rivalries in both units for identical figures from both sides,
  and the pair-words property. `test/worker/head-to-head.test.ts` covers
  both accounts agreeing, a re-sent finish counting once, aborted games,
  pre-0054 rows, the schema 3 → 4 upgrade, the backfill re-send, a third
  account, and nicknames.

### The review, in plain terms

**Round 1, CLEAN.** Exactly-once holds: the pair id rides the same
`transactionSync` upsert, and the other distance cannot change after the
first send. No `sub` reaches a phone; brute-forcing a pair id is
infeasible (about 10^20 work); every route probe gave the expected 401,
403, 404, 400 or 405. The migration is safe, and `/api/record` is still
one call. All six optional items were taken:
- "the other way around", in American English;
- the nickname shown in its own style, not the all-caps section heading;
- Clear shown right after the first save;
- no account stamp (a write) when naming answers 404;
- the backfill test now proves the re-send happens by itself, by storing
  the old-shape digests instead of deleting them;
- "once both have landed" in 0054 and on the screen.

## What was learned

- `ALTER TABLE … DROP COLUMN` in workerd's SQLite failed ("incomplete
  input") on a table whose `CREATE` text has a comment inside it. The
  upgrade test rebuilds the old table instead. Production only ever adds.
- Deleting a game's stored pair id is not enough to make a re-send: the push
  recomputes it before comparing digests. Only a line accepted in the old
  shape triggers it, which is the real pre-0054 case.
- A Python heredoc wrote `​` escapes into a TypeScript regex as the
  characters themselves. Write such lines with a script file.
