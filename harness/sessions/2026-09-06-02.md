## What was learned

- **`ctx.id.name` is not a safe source for the account key.** It is only
  populated for a name-derived id, so a stub obtained any other way yields
  `null`. The `sub` is passed into `touch()` explicitly instead — an account row
  that is sometimes anonymous is worse than one that is always explicit.

- **Two tests were asserting the *absence* of this stage**, and both had to
  change rather than being left alone:
  - `smoke.test.ts` asserted `UserDO` answers 501. It now asserts what is
    actually load-bearing — that `idFromName` is deterministic per `sub` — which
    is the GameDO join-code test's twin and should have been the assertion all
    along.
  - `identity.test.ts` used `toEqual` on the `/api/me` body, so adding a field
    broke it. Loosened to `toMatchObject` with a note that the account is
    `user-do.test.ts`'s business.

  Worth noting as a pattern: a test that pins a stub's shape becomes a tripwire
  the moment the stub is filled in, which is fine, but it means "the stage is
  done" and "a test failed" arrive together and the failure must be read before
  it is fixed.

- **An absence assertion passes for free against an empty list.** The decision
  0017 test checks that `fields` has no `owner_sub`/`player_id` column via
  `PRAGMA table_info`. If that PRAGMA ever returned nothing the test would be
  permanently and silently green, so it now asserts two columns that *should* be
  there first. Caught while writing it, not by it failing — the same shape as the
  `check-qr` / `check-invite` split already recorded in STATE.md.
