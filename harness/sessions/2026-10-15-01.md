## What was done

Phase 2 of run 3 (`harness/pipeline/ratchet.md`): **O-57**, other games on

- **Three parts per game** (`shared/games/types.ts`):
  - **Descriptor** (`shared/games/chess.ts`, `catalog.ts`). Both the Worker
    and `app.js` hold it. It has the name, lattice, start zone, piece
    letters, promotion choices, options, the record format, and the
    **position codec**: reading a FEN, and moving a piece the server already
    called legal. That codec moved here from `optimistic.ts`, `render.ts`
    and `replay.ts`.
  - **Rules** (`worker/games/chess.ts`). These are chess.js, moved unchanged
    out of `GameDO`: `stops`, `play`, `ending`, `timeout`, the PGN.
  - **Art** (`client/games/`). The cburnett pieces and the PGN writer, built
    as their own file, `/games/chess.js`. The phone fetches it with a
    dynamic import (`registry.ts`) when a board, review, preview, watch page
    or account screen first needs it.
- **A carry is a lift, waypoints, a place.** The `waypoint` message
  (`{t, to, pos}`) is defined. The storage is `carry.via_json` and
  `moves.via_json`. `onPlace` judges the last leg from the last stop. Chess
  never has a waypoint, and the server has no `waypoint` handler yet, so one
  sent in a chess game is answered as an unknown type, exactly as before.
- **Schema 9** adds `game.game_type` (NULL is chess) and `options_json`.
  **Absent is chess** everywhere: snapshot, watcher view, report, archive and
  join answer carry `gameType` only for a game that is not plain chess. A
  create request with an unknown type gets a 400. A stored unknown type has
  its moves refused.
- **The build** (`scripts/build-client.mjs`) makes two bundles, not esbuild
  code splitting, whose hashed shared chunks the static service worker could
  not precache. The game import is rewritten to `/games/chess.js?v=<hash>`.
  The build fails if `app.js` bundles a game's art or any client file
  bundles chess.js.
- **The service worker** precaches `/games/chess.js` (the `GAME_ART` list)
  and answers a versioned request only with that version while online. When
  offline, or when the server returns an error, it answers with the latest
  copy it holds.
- **Bundle:** `app.js` went from 225,428 B (76,922 gzip) to 214,815 B
  (72,429 gzip). `games/chess.js` is 13,921 B (5,230 gzip), fetched once.
- **`scripts/check-golden.mjs`** is new. It plays seven games over HTTP and
  WebSocket against two servers (old and new) and compares what they leave
  behind. The games cover two checkmates, both castlings, en passant both
  ways, an underpromotion, a resignation, a stalemate, an agreed draw, a
  loss on time and an abort. It compares the PGN, the review report, watcher
  frames, each player's own frames, the raw KV archive, and the PGN and
  report served from the archive. Old against new: **identical in all 63
  parts, 323 player frames included.** Old against old was identical too, so
  the normalising is stable.

## Judgement calls

- **The position codec stays in `app.js`.** The move prediction and the
  replay need it without a wait. It is a few hundred bytes and decides
  nothing.
- **"Absent is chess" instead of writing `chess` everywhere.** Every chess
  message, file and archive stays byte for byte what it was, and one rule
  covers old rows, old archives and old phones.
- **The storage columns were added now.** They are unused by chess but
  reviewed while nothing can depend on them.
- **The promotion picker is built when it first opens**, from the
  snapshot's game.

## What was learned

- **Threefold repetition never ends a game (O-59).** The server builds each
  position from the stored FEN alone, which has no move history. This was
  kept on purpose, since this phase promised no behavior change, and a test
  documents it. The fifty-move rule works, because the FEN carries the move
  counter that rule needs.
- **`check-review` and `check-record` flake under load (O-60).** The first
  tap of "Fool's mate, every piece carried" is never sent and the driver
  times out. It fails at HEAD `762d8f3` as well, so it is older than this
  work. A screenshot before each tap made it pass eight times in a row,
  which points to a race with the last GPS fix. The unconfirmed guess is
  that the tap lands on the piece-in-hand plate.
- **A wrapped PGN cannot be compared across runs as text.** A carry's
  seconds move the line breaks. The golden script compares the movetext as
  one line of tokens.
