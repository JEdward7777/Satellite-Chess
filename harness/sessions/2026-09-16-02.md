## What was learned

**Deleting a seat key has a blast radius shaped like "every test that opens a
socket".** The prediction was four router-path tests in `game-do.test.ts`; the
reality was 85 failures across four files, including all 58 in `carry.test.ts`.
It was still a small fix — each of those files funnels socket-opening through
exactly *one* helper, so it was one edit per file. That is worth saying plainly
because it is an argument for a habit the project already has: the cost of a
cross-cutting change is set by how many places construct the thing, not by how
many places use it.

**The dev seam's second lock guards reading a token, not just minting one — and
that reached further than expected.** Three worker test files addressed
`https://example.com`, so a dev cookie handed to them was correctly ignored and
every socket refused. They had to move to loopback. This is decision 0029 working
exactly as designed (and it has its own test), but it is a non-obvious
consequence: **a test that wants a dev session has to look local**, because that
is what the seam means. The tests are more honest for it — they now exercise the
real seating rule instead of a query-string bypass.

**A signed value still needs validating on the way out.** `safeNext` runs at
`/login` *and* at `/callback`. Not because the cookie can be tampered with — it is
HMACed — but because a flow sealed by the *previous deploy* has no `next` field at
all, and would deserialise to `undefined`. Rejecting that would fail an in-flight
sign-in as "expired", which on a mandatory-sign-in app reads as a loop. It
normalises to `/` instead. Ten-minute window, but it is the kind of thing that
only happens to real users and never in a test.

**A peer session with "a browser on another machine" turned out to be in *this
working tree*.** The driver run was delegated to another session on the operator's
say-so, and the bisect instructions sent to it included `git checkout <old-commit>`
— which would have moved `HEAD` in `~/Sync/projects/Satellite-Chess`, on top of
three files being edited at that moment. It cost nothing only because the peer
noticed, refused, and used a detached `git worktree` in scratch space instead.

The assumption that did the damage was never stated and so was never checked:
"another session" was read as "another machine". Sessions are not sandboxes from
each other. The rule is now in `reference/container.md`, where it will be read
*before* delegating rather than after: assume a shared tree, never send a command
that moves `HEAD` or stashes or cleans, and say which paths you are editing. The
cheap test is `pwd` at both ends, and it costs one line of a message.

**The delegation earned its keep twice over.** Beyond the two stale runbooks it
exposed, the peer bisected *two* commits rather than the one asked for, which is
what proved `check-invite`'s handicap failure was not a regression at all — it had
never passed at any commit, including the one our own records call "all eleven
passed". A record of a green run is worth exactly as much as the run was careful.

**The three-state launch check is the part to defend.** Sign-in is mandatory, so
the obvious shape is a boolean, and the obvious boolean is a bug that is invisible
on a developer's machine: an unreachable server is not a sign-out, and treating it
as one shows a sign-in screen to a player standing in a field with a fortnight-old
session. Written into 0035, `gotchas.md`, and the stage line, because one copy
would not survive.

## Loose ends not worth a stage

- **O-15 resolved**, moved to `resolved.md` with the outcome and the rejected
  alternative.
- **O-01 updated.** Mandatory sign-in blocking a game in the field stops being
  theoretical the moment the gate exists. Rule 2 of 0035 mitigates the returning
  player with a live session; it does nothing for the friend who has never signed
  in and is standing in a park on one bar, and nothing will short of the fallback
  0014 rejected. Flagged for phase 10.
- **Observed but not logged**: a tap while the socket is down produces no
  feedback tied to the tap. There is no outbound buffer — `net.ts` drops the
  message and `optimistic.ts` deliberately refuses to predict anything unsent,
  which is right — and the board's prompt does read "Reconnecting…". So it is
  arguably already covered, and inventing a queue would be worse than the silence.
  Worth *looking at* during phase 10 rather than logging as a defect now.
- `driver-console.mjs`'s header claimed every driver but one never signs in. That
  is now false, so it was rewritten rather than left next to the correction —
  which is the lesson the previous session wrote down.
- **The driver run was handed to `bob-mightymen`**, a peer session with a browser,
  at the operator's direction. Awaiting results at the time of writing.
- **Writing instructions for someone else found two bugs in our own docs**, and
  neither would have been noticed from the inside. Eight driver headers still
  said `npx wrangler dev --port 8799 --local`, and `container.md` stated flatly
  that `check-fields.mjs` was "the only one that needs the dev seam". Both were
  true yesterday. The second pass (commit `5857c53`) mattered more than the
  first: the *runbook the driver list actually sits in* was still wrong after the
  first fix, because the correction went to the top of the file and the commands
  are at the bottom. That is the 2026-09-16-01 lesson recurring inside a single
  day — **a correction only works if it is in the place the wrong thing is read
  from** — and it was caught by grepping for the pattern rather than trusting the
  first fix, which is the O-07 habit applied to prose.
  The transferable bit: **hand-over is a test**. Nothing else in this project
  reads its own instructions as instructions.
