## What was done

Phase 5 of the pipeline run (`2026-09-23-01`, `-02`): **`8.4` and `3.6.2`**,
implemented and taken through **two review rounds** to a clean verdict. One
commit carries all of it. Decision **0042** amends 0025 rule 6.

- **A finished game leaves as an archive, and its object ceases to exist.**
  - **When:** a day after anybody last looked at it (the result, a re-join, a
    socket closing), the game is archived to a new KV namespace, `ARCHIVE`. Its
    Durable Object then deletes everything.
  - **The archive:** one value at `game/v1/<CODE>`, holding the PGN byte for
    byte plus the review report. Positions are board space, built by a
    whitelist (`worker/archive.ts`). No coordinates, no field, no accounts, no
    join code in the value, and no expiry.
  - **The rule:** `worker/collection.ts` (pure).
  - **The steps:** `GameDO.retire`, one per `gc` firing, re-derived from stored
    columns each time: (a) record and index lines landed; (b) write; (c) 10 min
    settle and a read-back of the same PGN; (d) a synchronous re-check of the
    deadline and open sockets, then `deleteAll`.
- **Everything reads the archive once the object is gone.** That covers
  `/review`, `/pgn`, a re-join (it answers `{archived, color}` and the phone
  opens the review), and `GET /api/game/:code`. The seat check asks the
  player's own account (`UserDO.seatIn`: record line, else index row), so the
  archive needs no account. Strangers get the same 404 as a code that names
  nothing.
- **Nothing resurrects an object.** The schema is created only by `create` or
  on the wake of an object that already has tables. Every path checks
  `hasGameTables` first. Collection no longer re-creates the empty schema
  after `deleteAll`, which had kept every collected code (and every stray peek)
  alive for ever. An archived code is never handed out again.
- **`3.6.2`:** *abandoned* now means **unplayed**: both seats taken, no move,
  and not a pause somebody could claim, left for 30 days. Such a game is
  deleted and its index rows dropped. A game with moves and no result is never
  collected (0025).
- **O-34 closed:** the field goes to anybody only while a seat is free, and
  after that only to the two players. The privacy statement says so.
- **A board that outlives its game** (`client/net.ts`): after three refused
  upgrades in a row the phone asks once over HTTP. `archived` opens the review,
  a missing game gets a sentence, and both stop retrying.
- **Driver:** `check-review.mjs` steps 9–12, through a loopback-only
  `POST /api/dev/game/:code/collect`. That call sets every collection duration
  for one game (floor 1 s) and lets the real alarm run the real steps. A
  sleeping phone (a socket cut with `routeWebSocket`) wakes onto the review and
  stops retrying. "Your games" and a deep link open the archived review with the
  same file. A stranger gets 404.

### What each review round found, in plain terms

1. **A phone left on the board would retry for ever once the game was
   deleted.** A phone that slept with the board up woke to a deleted game and
   showed "Reconnecting…" indefinitely. Every 10 s it spent a Worker request, a
   session read and an object request: about 8,600 requests a day per forgotten
   tab. The reviewer reproduced it in a browser. The fix is to ask the server
   after three refusals and then stop.
   **And a paused game was deleted the instant its claim opened.** A game
   suspended before its first move, by one player, counted as "unplayed" and was
   collected on day 30. That is exactly when "Your games" and the board promise
   the other player a claim. Such a game is now never collected. Five smaller
   items were also taken:
   - a re-join during the last read-back cancels the delete;
   - a read-back that keeps disagreeing counts toward the retry cap;
   - the retry ladder was actually ~8.5 h against a comment saying 17, and is
     now 12 attempts (~34 h), longer than a UTC day, so a hit KV write cap
     resets first;
   - the dev knob has a 1 s floor;
   - the privacy wording no longer promises "a day" and mentions the field's
     name stays.
2. **Clean.** The reviewer killed and restarted `wrangler dev` mid-game with a
   board open, both signed in and with cookies cleared, and the board never
   declared a live game gone. Two small items were taken:
   - the unplayed and unclaimed deletes now re-check synchronously after
     `dropIndex`'s await, so a join, re-join or start in that gap keeps the
     game;
   - "missing" now reads "This game isn't on the server, or you're signed out",
     because a signed-out phone is told "no game" about an archived one.

## What was learned

- **Storage is existence, and the old code created storage on every read.**
  `applySchema` in the constructor meant any request to any code (a typo, a
  stranger, a phone re-opening a deleted game) made a permanent object. The
  "empty schema after `deleteAll`" in the old `collect` kept every collected
  code alive too. Deletion was never actually happening. The fix had to be at
  the constructor, not at the delete.
- **A timer is a hint, not a verdict.** Re-deriving the deadline from stored
  columns every time `gc` fires is what makes re-joins, open boards and old
  pre-8.4 games safe. The consequence for tests is that moving `timers.due_at`
  alone now re-arms rather than collects (gotchas.md says so).
- **Every await before a delete is a window.** Round 1's read-back race and round
  2's `dropIndex` race are the same bug in two places. The rule is to re-check
  synchronously, with nothing awaited between the answer and `deleteAll`.
- **Deleting a server object creates a client state nobody designed for:** a
  screen still pointing at it. The WebSocket upgrade tells the browser nothing
  about why it failed, so only an HTTP request can find out.
- **A rule that deletes on day N must be checked against every promise made
  about day N.** The claim window and the unplayed TTL were both 30 days.
- Test counts: 971 at the start, **1016** at the end.
