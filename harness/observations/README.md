# Observations

Real problems, spotted in passing, that are **out of scope for whatever is being
worked on** and not yet understood well enough to become a stage.

This exists so that noticing something does not force a choice between derailing
the current task and forgetting it. Write it down, keep going.

- [`open.md`](open.md) — live list.
- [`resolved.md`](resolved.md) — moved here once promoted to a stage, fixed, or
  dismissed. Keep the outcome; a dismissed observation is worth as much as a fixed
  one, because it stops the next session re-raising it.

Check `open.md` before "discovering" a problem. Half of them are already here.

Entry format — keep it short, one to five lines:

```markdown
### O-NN — One-line summary
**Spotted:** YYYY-MM-DD, stage N.N
**Why it matters:** the consequence, concretely.
**Not doing yet because:** scope, or unknowns that need resolving first.
```

Promote an observation to a stage when it is understood well enough to scope. Move
it to `resolved.md` with a pointer to the stage or decision that absorbed it.
